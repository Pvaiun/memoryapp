# Memory — app audit (2026-07-28)

Scope: full read of the worker (`brain.ts`, `capture.ts`, `push.ts`, `items.ts`, `db.ts`, `index.ts`, `ai.ts`, `embeddings.ts`), the shared logic (`dates.ts`, `cadence.ts`, `cards.ts`, `priority.ts`, `heuristicParse.ts`), the React app, the service worker, migrations, and the 2026-07-27 brain snapshot (32 items → 6 bubbles, minimal prompt, noHistory). Timezone/cadence claims below were verified by executing the actual functions under `TZ=UTC`, `TZ=Pacific/Auckland`, and `TZ=America/New_York`. All 219 tests pass and typecheck is clean — none of the bugs below are covered by the suite, which pins UTC.

The codebase is unusually disciplined: reliable-vs-advisory split is real, LLM output is sanitized everywhere, guarantees live in code, comments explain *why*. The findings are mostly (a) a systemic timezone-model problem, (b) a handful of genuine logic bugs, (c) product gaps the snapshot itself demonstrates, and (d) frontend resilience/accessibility debt.

---

## 1. The timezone model is the biggest systemic risk

The app stores one number, `tz_offset_minutes`, last reported by the client, and applies it as a *fixed* offset to every instant — past, future, worker-side and (differently) client-side. You are in America/Toronto: the offset flips −240 ↔ −300 twice a year, and several verified bugs fall out of this one modeling choice:

- **`sleepDayDiff` (worker) vs `sleepDayDiffLocal` (client) disagree across a DST boundary** (`src/shared/dates.ts:185` vs `:191`). Verified: a Nov 10 deadline viewed on Oct 30 reads `+10` days on the card notch and `due=+11d` in the Brain's input. The "one day-counting system" invariant the code comments claim (`dates.ts:167-173`) does not hold across a transition.
- **The 5am cron computes the wrong map day for ~1h after each DST shift** (`dates.ts:208` with the stale stored offset vs the client's `localDay()` in `src/app/api.ts:7-9`), and the 9pm push sweep fires an hour off, until the client happens to hit an endpoint that refreshes the offset.
- **Cadences *without* `atTime` are evaluated in the runtime's frame, not the user's** — `happeningToday` (`cadence.ts:274`), `cadenceStanding` (`brain.ts:557`), and the recurring-HAPPEN push path (`push.ts:107`) call `nextOccurrence()` bare, so `byWeekday` matches **UTC** weekdays. For UTC−4/−5 that's wrong for 4–5 hours of every day; "weekly on Tue" garbage-night logic can shift a day depending on when it's asked.
- **`nextAtTimeOccurrence` is only correct when the runtime is UTC** (`cadence.ts:374-391` pre-shifts instants and then `nextOccurrence` does its walk with *local* `getDay()`/`setDate()` calls, `cadence.ts:310-353`). Workers run UTC so the server is fine, but every **browser** caller (`bubbleStatus.ts:68`, `ItemRow.tsx:43`, `DescentView.tsx:183,1056`) runs in your local zone. Verified: a weekly-Monday-8pm cadence evaluated under `TZ=Pacific/Auckland` returns the wrong weekday *and* week. Your own machine is UTC−4: the client-side lateness/next-turn displays are affected today, not hypothetically.
- **Biweekly rhythms slip phase across spring-forward** — `weeksFromAnchor` divides by exactly 7×86 400 000 ms (`cadence.ts:319`, `:410-415`). Verified: an every-other-week anchor straddling the March transition inverts phase permanently. Your actual data hits this: therapy is `every 2 weeks on Wed at 10am` (i16 in the snapshot).
- **Migration 0007's day-precision backfill only matches rows written under the currently stored offset** (`migrations/0007_date_precision.sql:29-36`) — items captured in the other half of the DST year keep `date_precision='time'` and go "late" at 12:01pm again, the exact regression the migration fixed. One-shot, never self-heals.

**Recommendation (one fix, kills all six):** store the IANA zone name (`America/Toronto`) instead of / alongside the raw offset — the client has it for free (`Intl.DateTimeFormat().resolvedOptions().timeZone`) — and derive the offset *per instant* with an `Intl`-based helper (no library needed in a Worker; ~15 lines with `formatToParts`). Make `sleepDayOf`/`sleepDayDiff`/`nextOccurrence` take the zone, delete `sleepDayDiffLocal` (client and worker then share one function), and run the cadence walk entirely in user-local wall time. Add a DST-straddling test matrix and run the suite under a non-UTC `TZ` (today `bubbleStatus.test.ts:8` pins UTC and the whole class of bugs is structurally invisible).

## 2. Real logic bugs, independent of timezones

1. **Recapture resurrection of decayed priority boosts** — `capture.ts:92-93` writes `matched.priorityBoost + RECAPTURE_BOOST` (the raw stored sum) while resetting `boost_updated_at` to now. A 0.15 boost that had decayed to ~0.01 over 84 days springs back to a full 0.30. Over months of recaptures the boost saturates and priority stops discriminating. Fix: fold decay in first — `decayedBoost(matched.priorityBoost, matched.boostUpdatedAt, now) + RECAPTURE_BOOST`. (`undoRecapture` at `capture.ts:181-184` has the mirror-image issue: it subtracts but leaves the freshened anchor.)
2. **Monthly/yearly cadence math is wrong** — the monthly walk can fall through its loop and return the 1st-of-month cursor, ignoring `byMonthDay` and interval phase (`cadence.ts:330-346`; verified `{monthly, interval:36}` anchored Jan 15 2026 → Feb 1 2028); yearly ignores anchor phase (`{yearly, interval:2}` anchored 2020 → 2027). Nothing in the suite tests monthly or yearly at all. "Renew passport every year" / "pay rent on the 1st" class items will misfire.
3. **Push alerts are marked sent before they're sent** — `push.ts:209-212` inserts into `sent_alerts`, *then* attempts delivery. A transient push-service failure (or Worker eviction mid-loop) permanently eats that one-shot alert — and these are exactly the alerts the spec calls the reliable floor. Fix: write the idempotency row only after ≥1 successful delivery, or record per-subscription outcomes.
4. **One Brain hiccup at 5am = fallback map all day** — if the LLM call throws, `rebuildMap` stores the deterministic fallback and sets `map_day` (`brain.ts:214-221`, `:306`), so every subsequent open returns it; nothing retries. Fix: retry the Brain call (2–3 attempts, backoff) and/or treat a `mode='fallback'` map as stale on the next `/api/map` open so first-open upgrades it. The snapshot records `mode` already — use it.
5. **A transiently-failed embedding poisons an item forever** — `embed()` silently falls back to the 384-dim trigram vector (`embeddings.ts:11-23`); stored next to 768-dim bge vectors, `cosine()` returns 0 on dimension mismatch (`db.ts:266`), so that item is permanently invisible to recapture-match and semantic search. Fix: store NULL on AI-backend failure and backfill lazily (a nightly "re-embed items whose dims ≠ expected" sweep in the cron is ~10 lines).
6. **`HAS_MONTH_OR_RELATIVE` swallows ordinary words** — `dates.ts:18` has no trailing boundary: `\bmay` matches "maybe", `\bdec` matches "decide"/"declog", `\bmar` matches "market". Consequence: "maybe do the taxes on the 20th" skips ordinal expansion and **drops the date entirely**. Fix the regex (`\b(?:jan|feb|…)\b` style) and add cases.
7. **`occurrencesBetween` truncates at 100 silently** (`cadence.ts:357-367`) — a daily cadence across the calendar's 60-week window returns a partial list the calendar paints as complete. Raise the cap for the daily case or window-clamp the caller.
8. **`isNeglected` (×1.5 period) and `neglectedByDays` (×1.0) use different thresholds** (`cadence.ts:58` vs `:288`) — "slipping=2d" can appear in the Brain's input while the neglected flag is still false, and vice versa.

## 3. What your own snapshot shows (product-level)

Grounded in the 2026-07-27 build you attached:

1. **Card-grammar compliance silently failed — zero markup in all six sentences.** No `**bold**`, no `[chip](id)` anywhere in the stored output (e.g. `"Kyle comes over at 7pm tonight."`). The client saves the day for chips (`withMemberChips`, `cards.ts:43`, appends bare chips), but: chips land *after* the prose instead of inline (with no separator after the period — `cards.ts:52` joins with a bare space), and `farTokens` returns `[]` so the descent far-form degrades to the bubble name. Suggestions: (a) count markup compliance in the snapshot (`bubblesWithoutChips`, `boldTokenCount`) so prompt regressions are measurable instead of invisible; (b) worker-side fallback — if a non-rotation sentence has no chips but a member DO's title appears verbatim in it, linkify in place; (c) derive far-form tokens from member titles when the prose is unmarked; (d) add a separator ("· " or leading "— ") before appended chips.
2. **Tomorrow's two timed appointments vanished — and they're 20 minutes apart.** i13 "Phone call from triage nurse" (+1d, 12:40pm) and i17 "Meeting with Manulife guy" (+1d, 1pm) — both shown 10× on previous maps (there was even a vocabulary name "Tomorrow's appointments") — got no bubble at all. The only remaining net is the 45-minute-lead push. For a planning-ahead user that's the difference between knowing tonight and finding out at 11:55am; and nothing anywhere notices that a 12:40 phone call collides with a 1pm meeting. Suggestions: (a) extend the deterministic floor: timed HAPPENs within ~36h get at least a quiet mention (a code-side "Tomorrow" catch bubble mirroring "Also today", `brain.ts:280-295`); (b) a tiny deterministic overlap check when two timed events land within N minutes — surface it in the bubble prose or as a one-line warning. The Brain can't be trusted with this (this run proves it); code can.
3. **Day-precision hard deadlines get zero runway.** i21 "conversation with Kayla about bed shopping" is `due=+4d(hard)` day-precision, shown 7×, and was dropped from this map. The runway push path explicitly skips day-precision (`push.ts:123`), so if the Brain keeps dropping it, the *first* signal is the 9pm sweep **on the due day** — after the day is gone. Suggestion: give day-precision hard deadlines an effort-scaled *day-level* runway via the existing evening sweep ("due in 2 days" entries for medium/large effort), or fold "hard deadline within runway days" into the map's code-side floor.
4. **Duplicates survive: i28 "Book driving lesson" and i29 "Book driving class"** — 8 days old, both shown 7×, obviously the same errand. Capture-time adjudication only sees the current capture; nothing ever reconciles the corpus afterward. Suggestion: a weekly dedup pass (embedding pairs > ~0.9 among active items → one cheap-tier adjudication call → a "merge?" nudge in the review sheet). The undo machinery for merges already exists.
5. **The profile is describing app mechanics again.** "…done almost every day but *only after a lot of back-and-forth completion/undo cycling, suggesting some ambivalence or distraction around logging it*" — that's the user operating the app, which the profile prompt explicitly forbids, and it's exactly the leak class that once made the Brain drop a same-day item. `compactEventLines` collapses capture/edit churn but **not completed→completion_reverted toggles**. Suggestion: collapse complete/uncomplete pairs within ~10 minutes into one line (or a `(xN toggles)` suffix), same as draft churn.
6. **Rotation never fires under the minimal prompt.** This map has no rotation bubble; keep-warm KNOWs like i3 (bathroom-lingering habit) have no other route to the surface, and reference KNOWs correctly shouldn't rotate. Suggestion: track rotation frequency in snapshots; if it stays ~0, add a deterministic fallback (e.g. if ≥2 keep-warm KNOWs unseen 7+ days, append the dot bubble in code, like "Also today").
7. **First-open-of-day latency when the cron missed**: the on-demand rebuild path runs profile → librarian → Brain *serially* (`brain.ts:144-164`) — three LLM round trips behind the "calculating" screen. Parallelize profile+librarian, or reuse yesterday's profile on the interactive path and refresh it in `waitUntil`.

## 4. Frontend reliability & UX

(High-impact subset; file:line refs verified.)

1. **Failed first-of-day rebuild = blank app.** If `rebuildMap` throws, the gate at `App.tsx:579` collapses, `map` stays null, and `<main>` renders nothing — a 6s toast, then an empty screen, no retry. Add an error state with a Retry button.
2. **Offline capture loses the core promise.** The catch at `App.tsx:340-343` restores the textarea in memory only; `sw.js:18` skips `/api/*`; no queue, no Background Sync. "Typed it, it's filed" fails precisely when the network does — and this user captures at 1–5am on a phone. Fix: persist unsent captures to localStorage and flush on `online`/next open (small), or Background Sync (bigger).
3. **Search results never refresh after actions** — `SearchView` is the only view without `refreshKey` (`App.tsx:644`) and holds results in local state; ticking a checkbox from search appears to do nothing. It also has no response-ordering guard and no catch (`SearchView.tsx:23-38`).
4. **Push flow dead-ends**: a denied permission exits silently (`App.tsx:551-552` — the bell just "does nothing"); there is no unsubscribe path at all once enabled; `sw.js` has no `pushsubscriptionchange` handler, so an expired subscription reports "on" while delivering nothing; and `notificationclick` ignores the `itemId` it was handed (`sw.js:44-59`) — tapping "Time for this now" opens the generic map. Deep-link (`/?item=<id>`) + an unsubscribe button + a "notifications blocked in browser settings" toast are all small.
5. **Swallowed errors**: Browse renders "Loading…" forever on a failed fetch (`BrowseView.tsx:150,192`); Calendar renders an *empty calendar* on failure — reads as "nothing scheduled" (`CalendarView.tsx:264`); ItemSheet save/delete have no catch (`ItemSheet.tsx:100-135`) — a failed PATCH is indistinguishable from not having tapped. One shared error+retry affordance would cover all of these.
6. **Stale map across 5am if the app stays open/visible** — the only refetch trigger is `visibilitychange` (`App.tsx:244-247`); a phone left on the charger with the app foregrounded shows yesterday's map with yesterday's date. Add a timer that checks `localDay()` rollover (DescentView already runs a scheduling timer to piggyback on). Related: overlapping `loadMap` calls can double-fire the rebuild (`App.tsx:232-253`) — add an in-flight guard.
7. **Tiles renderer never shows the Brain's sentence, chips, or firstStep** (`MapView.tsx:153,197`; `BubbleMap.tsx:90-93`) — the whole card-prose layer is unreachable for anyone on "Tiles (classic)". Either render `parseSentence` there too or retire the setting.
8. **No undo where it matters.** `Toast.action` is fully built and dead (`App.tsx:38,175,738-747`) — no caller passes an action. Completing, dismissing, and deleting (a bare `confirm()`) have zero undo, in an app for mis-taps at 2am. Wiring "Done — Undo" / "Dismissed — Undo" through the existing toast-action plumbing and the existing `uncomplete`/`reopen` endpoints is nearly free.
9. **Accessibility is systematically absent**: chips are `<span role="checkbox">` with no `tabIndex`/keyboard handler *nested inside a `<button>`* (`DescentView.tsx:1057-1107`); no sheet has `role="dialog"`/focus trap/Escape; toasts have no `aria-live`; list rows are `<div onClick>`. If this ever serves anyone but you on a touchscreen, budget a pass; the nested-interactive chip is worth fixing regardless (it breaks in some browsers' event handling too).
10. **Service worker cache hygiene**: responses are cached without an `res.ok` check (`sw.js:20-28`) so a 500 page can become the permanent offline shell; the `v1` cache name is never bumped so `activate` cleanup never deletes anything.

## 5. Smaller / housekeeping

- **Export exists, import doesn't** (`index.ts:153-179`) — a backup you can't restore. Add `POST /api/import` (validate `format: 'memory-v1'`, wrap in a transaction).
- **Anthropic calls have no retry** for 429/529/5xx (`ai.ts:11-42`) — one overloaded minute at the wrong time degrades capture (heuristics) or the day's map (see §2.4). A 2-retry backoff helper is ~10 lines and improves both.
- **D1 writes are sequential** where `db.batch()` would do — `rebuildMap`'s delete+insert loops (`brain.ts:240-304`) and `setItemThemes`. At current volume it's latency, not correctness; batching the rebuild also shrinks the window in which a concurrent `getMap` sees a half-built day.
- **Missing indexes**: no reverse index on `bubble_items(item_id)` or `item_themes(theme_id)` (Browse's main join), no composite `items(status, ...)`. Trivial migration.
- **FTS sync is convention, not structure** — any future write path that forgets `syncFts` desyncs search silently. FTS5 external-content + triggers makes it impossible to forget.
- **`undoRecapture` re-parses with heuristics only and without tz** (`capture.ts:189,196`) — a re-split "call dentist tomorrow" resolves "tomorrow" in UTC and loses LLM-quality parsing. Pass tz at minimum.
- **Night-owl edge**: at 4:30am, "at 3am" resolves to 3am *today* — 90 min in the past (`dates.ts:87-89`).
- **Heuristic parser**: recurring DOs drop their date phrase ("every Monday starting July 6" loses the anchor, `heuristicParse.ts:106`); bare `could` marks items optional (`dates.ts:161`).
- **Dead code**: `api.items()`, `BubbleMap.width`, `api.rebuildMap`'s unused `promptVariant` param, `DescentView.tsx:745` dep-array-less effect re-priming the rAF loop every render.
- **Test gaps that guard the above**: no non-UTC/DST runs, no monthly/yearly cadence tests, no boost-accumulation test, no `occurrencesBetween` cap test. Each fix in §1–2 should land with its regression test.
